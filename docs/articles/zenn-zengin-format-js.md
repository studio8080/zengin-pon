給与振込や総合振込を「ネットバンキングに一括で取り込むファイル」は、いまも全銀協が定めた固定長の形式（いわゆる全銀フォーマット、FBデータ）が使われています。Excel の一覧からこのファイルを作るツールをブラウザだけで動く形で作ったので、実装してわかったはまりどころをまとめます。

仕様の全体像は別に解説ページを用意しています。
https://zenginpon.kokokikaku.com/zengin-format.html

## 1レコード120バイト、4種類のレコード

ファイルは、1行120バイトのレコードが次の順に並んだものです。

| 区分 | 先頭の1桁 | 件数 |
|---|---|---|
| ヘッダー | 1 | 1 |
| データ | 2 | 振込の件数ぶん |
| トレーラー（件数と合計金額） | 8 | 1 |
| エンド | 9 | 1 |

項目は「文字項目は左詰め・空白埋め」「数字項目は右詰め・ゼロ埋め」の2種類しかありません。

```js
function C(str, len) { // 文字項目: 左詰め・空白埋め・超過は切り捨て
  const s = String(str == null ? '' : str);
  return s.length >= len ? s.slice(0, len) : s + ' '.repeat(len - s.length);
}
function N(val, len) { // 数字項目: 右詰め・0埋め
  const s = String(val == null ? '' : val).replace(/[^0-9]/g, '');
  if (s.length > len) throw new Error(`数値が桁数(${len})を超えています: ${s}`);
  return '0'.repeat(len - s.length) + s;
}
```

データレコード（総合振込）はこうなります。

```js
'2' + N(bankCode, 4) + C(bankName, 15) + N(branchCode, 3) + C(branchName, 15)
  + C('', 4) /* 手形交換所番号（未使用） */ + N(depositType, 1) + N(accountNo, 7)
  + C(name, 30) + N(amount, 10) + N(newCode, 1)
  + N(customerCode1, 10) + N(customerCode2, 10) + N(transferType, 1) + C(ediFlag, 1) + C('', 7)
```

組み立てたら、全レコードが120文字ちょうどかを必ず確かめます。足し算を1か所間違えると、銀行の取込画面で「レコード長エラー」とだけ言われて原因がわかりません。

## はまりどころ1: 半角カナの濁点は2文字になる

文字は JIS X 0201（半角英数と半角カナ）の1バイト文字だけです。「ガ」は半角では「ｶﾞ」の2文字、つまり2バイトになります。

受取人名の枠は30バイトなので、全角で数えて30文字に収まっていても、濁点・半濁点が多い名前は変換後にあふれます。**文字数の検査は、半角カナに変換したあとの長さで行う**必要があります。

## はまりどころ2: 長音「ー」は使えない銀行が多い

半角の長音「ｰ」は JIS X 0201 にある文字ですが、銀行の入力基準では使えないことが多く、ハイフン「-」に置き換えるのが決まりです。

```
エービーシー商事 → ｴ-ﾋﾞ-ｼ-ｼｮｳｼﾞ
```

同じく、中点「・」はピリオド「.」、小さい「ャュョッ」は大きい「ﾔﾕﾖﾂ」にします。拗音・促音を大文字で書くよう求める銀行が多いためです。

## はまりどころ3: 法人名は略語にする

「株式会社ここ企画」は、そのまま半角カナにすると「ｶﾌﾞｼｷｶﾞｲｼｬｺｺｷｶｸ」で、枠を無駄に使ううえに口座名義と一致しません。全銀協の「振込依頼書等記載要領」には法人種別の略語があり、位置で書き方が変わります。

| 位置 | 書き方 | 例 |
|---|---|---|
| 先頭 | 略語＋閉じかっこ | ｶ)ｺｺｷｶｸ |
| 末尾 | 開きかっこ＋略語 | ｺｺｷｶｸ(ｶ |
| 中間 | かっこで囲む | ｱｲｳ(ｶ)ｴｵ |

実装では、表に書かれがちな「(株)」「㈱」「カブシキガイシャ」をいったん「株式会社」に戻してから略語にします。`String.prototype.normalize('NFKC')` を通すと「㈱」は「(株)」になるので、先に NFKC をかけておくと書き方の揺れをまとめて吸収できます。

```js
const CORP_SHORT = [
  [/[(（]株[)）]/g, '株式会社'], [/[(（]有[)）]/g, '有限会社'],
  [/カブシキ[ガカ]イシャ/g, '株式会社'], /* ... */
];
```

略語の表は「特定非営利活動法人」のような長いものから先に当てます。短い「法人」系を先に当てると、長い名前の一部だけが置き換わります。

## はまりどころ4: 円記号とバックスラッシュ

JIS X 0201 の 0x5C は円記号「¥」です。JavaScript の文字列で `\` を書くと U+005C なので、そのまま1バイトにすれば 0x5C になりますが、画面に出すときは「¥」として見せないと利用者が混乱します。逆に、Unicode の「¥」（U+00A5）や全角の「￥」（U+FFE5）は 0x5C に寄せます。

```js
if (cp === 0xA5 || cp === 0xFFE5) b = 0x5C;                      // ¥
else if (cp >= 0xFF61 && cp <= 0xFF9F) b = 0xA1 + (cp - 0xFF61);  // 半角カナ
else if (cp < 0x80) b = cp;
else throw new Error(`エンコードできない文字: ${ch}`);
```

`TextEncoder` は UTF-8 しか出せないので、バイト列は自前で作ります。半角カナは U+FF61〜U+FF9F が 0xA1〜0xDF にそのまま対応するので、表を持たなくても引き算で済みます。

## はまりどころ5: 改行コードは銀行ごとに違う

レコードの区切りに CR+LF を求める銀行、改行なし（120バイトが続くだけ）を求める銀行、どちらでも受け付ける銀行があります。銀行の取込画面の説明に書いてあることが多いので、出力時に選べるようにしておくのが無難です。拡張子（.txt / .dat など）も同じです。

## はまりどころ6: ゆうちょ銀行の記号・番号

ゆうちょ銀行の口座は「記号5桁・番号8桁」で管理されていて、全銀フォーマットの「店番3桁・口座番号7桁」とは形が違います。総合口座（記号が1で始まる）なら、

- 店番 = 記号の2〜3桁目 ＋ 「8」
- 口座番号 = 番号の末尾の「1」を除いた7桁

という規則で変換できます。振替口座（記号が0で始まる）は規則が別です。

## はまりどころ7: Excel が数字を壊す

利用者の Excel は、口座番号「0012345」を数値の 12345 にしていたり、長いコードを `1.234567E+06` にしていたりします。コードと口座番号は、数値型・指数表記・末尾の `.0` を元の整数に戻してから桁をそろえます。

金額は逆に、マイナス（`-`、`△`、`▲`、`(1,000)`）を黙って正の数にしてはいけません。振込でマイナスはあり得ないので、エラーとして利用者に返します。

## 設計で決めたこと: 振込データを外に出さない

振込先の一覧は、取引先の口座情報そのものです。そこで、

- 変換はすべてブラウザの中で行い、ファイルの中身をサーバーに送らない
- 列の推定も名義の変換も、理由を説明できるルールで書く（AI や OCR で確率的に決めない）
- 漢字の氏名からカナを推測しない（読み方が一つに決まらないため。カナの列が無ければ利用者に入力してもらう）

という方針にしました。正しさの根拠を利用者が自分で確かめられることを、便利さより先に置いています。
