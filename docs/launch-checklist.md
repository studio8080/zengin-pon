## 3-4. 月払い・年払いの自動化（Cloud Functions）— **設定完了（2026-09-11）。テストのみ未実施**

### 仕組み

```
Stripe（支払い成功）──webhook──▶ zenginponStripeWebhook
                                  ├─ 商品（全銀ポン Pro）で絞る。ほかの製品のイベントは Firestore にも Stripe にも触らず素通り
                                  ├─ キーを発行 → Firestore（zenginponLicenses）に保存 → 購入者にメール
                                  └─ イベントIDで二重処理を防ぐ（zenginponEvents）。メールを送れなければ 500 で Stripe に再送させる

ブラウザ（期限10日前 か 前回確認から7日）──ライセンスIDのみ──▶ zenginponLicense
                                  └─ Stripe に契約状態を直接照会 ─▶ 新しいキー（契約中）／ 410（Stripe で解約を確認）
                                     ／ 503（Stripe に照会できず判断できない。ブラウザはキーを消さない）
```

キーの期限は `min(使ってよい最終日, 今日+30日)`。使ってよい最終日は契約の状態で決める（`functions/billing.js` の `entitledUntilOf`。
契約中は期間の末日+3日、日付指定の解約はその日+3日、再請求中（past_due）は期間の初日から30日+3日、未払い（unpaid）は今の期間の初日+3日、
一度も払われていない契約には出さない）。契約中は取り直すたびに延びるが、解約されると更新エンドポイントが `410` を返し、
**ブラウザが手元のキーを削除して無料プランに戻る**。`410` は Stripe（照会か署名付き Webhook）で解約を確かめたときだけ。
月払い・年払いとも Stripe のサブスクなので**自動更新は Stripe 側で行われる**。

## 4. 申し込みが来たときの作業（1件あたり 3分）

Stripe から決済通知メールが届いたら、次を実行する。

```bash
node tools/issue-key.js --months 12 --mail --memo "buyer@example.com"
```

- 月払いなら `--months 1`、年払いなら `--months 12`
- `--mail` を付けると**そのまま送れるメール文面**が出る。件名と本文をコピーして送るだけ
- 発行記録は `tools/issued-keys.csv` に自動で追記される（Git には入らない）

**手順3-4（Cloud Functions）を済ませていれば、この作業は不要**。支払いのたびに自動で発行・送信される。
この節は、Functions を入れる前に売り始めた場合と、返金・特例対応のための手動発行用。

### キーが届かないとき・「【要対応】」のメールが来たとき

- 届かない問い合わせが来たら、**まず Stripe の Webhook「zenginpon-license」→「イベントの配信」で失敗を探す**。原因を直してから再送する（同じイベントIDなら二重には送らない）。
- 急ぐときは同じライセンスIDのキーを手動で発行して先に送る（3-4 のメモの 2026-10-02 の手順。`node -e "console.log(require('./functions/sign').licenseIdFor('sub_…'))"` で ID を出し、`functions/sign.js` の `signKey` で署名する）。
- メールが送れないとき、Webhook は 500 を返して Stripe に再送させ、運営者（`MAIL_FROM` のアドレス）に「【要対応】全銀ポンのメールを送れませんでした」を送る。
- 購入者のメールアドレスが分からないときは「【要対応】全銀ポン: キーを送れませんでした」がキー付きで届く。顧客のメールアドレスを Stripe で確かめて、そのキーを転送する。
- 支払いが済んでいない申し込み（incomplete）は「【要対応】全銀ポン: 申し込みの契約が有効になっていません」。キーは送っていない。Stripe で支払いの状態を確かめる。
- Stripe の照会が権限不足で失敗したら 500（黙って諦めない）。制限付きキーの Subscriptions・Customers の読み取りを確かめる。
- 同じイベントが同時に届いたら、後の方は 409（Stripe が後で再送する。異常ではない）。
- キー更新が 503 を返すのは、Stripe に照会できず手元の記録でも判断できないとき。ブラウザはキーを消さず、次に開いたときに取り直す。

### 最小残高（2026-10-15 設定。共用アカウント）

設定 → 銀行口座と通貨 →「最小残高」＝**決済残高で ¥10,000 を維持**。毎週の入金からこの額を残し、返金（初回7日以内）と不審請求の手数料をすぐ処理できるようにする（有休ポンと共通）。
残高が足りないと返金は「保留」になり、マイナスが続くと Stripe が銀行口座から引き落とす。

### 返金するとき（初回決済から7日以内）

Stripe は返金しても契約を止めない。返金だけすると、次回も請求され、キーも延び続ける（有休ポンと共通の手順）。
1. Stripe の画面でそのサブスクリプションを**「今すぐキャンセル」**（「期間の終了時」ではない）
2. 支払いを返金する（全額）
3. 「ご契約が終了しました」のメールが届き、猶予（3日）後にキー更新が 410 になる

### 支払いに失敗したときの設定（確かめるだけ。共用なので変えるときは全製品で相談）

**確認済み（2026-10-12、ダッシュボードで読み取り）: 「支払いのリトライがすべて失敗した場合」＝サブスクリプションをキャンセル、「カード決済が失敗した場合にメールを送信」＝オン。** 変える必要なし。

設定 → Billing → サブスクリプションとメール →「再試行がすべて失敗した場合」。
`functions/billing.js` は `past_due`（再請求中）を今の期間の初日から30日＋3日まで、`unpaid`（未払いのまま）を今の期間の初日＋3日まで使わせる（2026-10-15 から。以前は期間の末日まで）。
Stripe は更新の請求書を作った時点で期間を次へ進めるので、ここが「未払いのままにする」「期日超過のままにする」でも、
払われていない契約にキーが出続けるのは最長でおよそ1か月に限られる。それでも**「サブスクリプションをキャンセルする」になっていることを確かめる**（Functions 側は保険）。
あわせて「支払いに失敗したときに顧客へメールを送る」がオンか確かめる（共通メモ5章の5）。

### 更新のとき

期限が近い購入者（`tools/issued-keys.csv` で分かる）に、新しいキーを同じ手順で発行して送る。
古いキーは期限切れで自動的に使えなくなるので、無効化の作業は不要。
