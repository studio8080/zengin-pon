## まとめ

金融の登録は要らない。表示まわり（特商法・個情法・外部送信）は今回そろえた。残りは下の「やること」。

## 関係する法令

| 法令 | 関係 | 求められること |
|---|---|---|
| 銀行法 2条17項（電子決済等代行業） | 1号は「預金者の委託を受けて、銀行に為替取引の指図を**伝達**する」、2号は「口座情報を銀行から**取得**して提供する」営業 | 該当しない。全銀ポンは銀行に何も送らず、銀行から何も取らない。利用者が自分でファイルを取り込む。**API連携や自動アップロードを足すと1号に当たりうる** |
| 資金決済法（資金移動業） | 為替取引を業として営む場合 | 該当しない。資金を預からず、動かさない |
| 特定商取引法 11条・12条の6 | 通信販売。サブスクは申込みの最終段階で、分量・価格・支払時期と方法・提供時期・解約条件を表示 | `tokushoho.html` と `pricing.html#confirm`。決済画面は Stripe なので、Stripe 側にも表示を足す（下記） |
| 個人情報保護法 17・21・23・25・28・33〜35条 | 購入者のメールアドレス、Stripe 顧客ID、契約状態を保有。委託先が米国事業者 | 利用目的、安全管理、委託先、外国にある第三者、開示等の手続きを `privacy.html` に記載 |
| 電気通信事業法 27条の12（外部送信規律） | 対象事業者にあたるかは微妙（小規模な自社サービスの提供）。義務の有無によらず、通知・公表しておくのが安全 | `privacy.html#external` に送信先・内容・目的の表 |
| 消費者契約法 8条 | 事業者の責任を全部免除する条項、故意・重過失の一部免除は無効 | `terms.html` は軽過失のみ上限つき。消費者の権利を妨げない旨を明記 |
| 景品表示法 | 優良誤認・有利誤認。比較表示は客観的な根拠が要る | 「どの銀行でも」「最速」のような断定を外した。比較表に調査日と注記 |
| 障害者差別解消法（2024年4月から事業者も合理的配慮が義務） | ウェブの対応は「環境の整備」で努力義務。申し出があれば合理的配慮 | `accessibility.html`。JIS X 8341-3:2016 AA に「配慮」。試験をしていないので「準拠」と書かない |
| インボイス制度 | 未登録 | 適格請求書を発行できないことを `pricing` `tokushoho` `faq` に明記済み |

## リスク

| リスク | 重さ | 手当て |

| 変換の誤りで誤振込が起きる | 高 | 変換後の件数・合計を画面に出す。銀行の画面で最終確認するよう全ページで案内。名義カナは推測しない。実銀行での取込テストを販売の本格化より先にやる |
| 「登録が要らない」説明が、機能追加で古くなる | 中 | `AGENTS.md` と本メモに条件を明記。API連携を検討するときは弁護士に相談 |

## やること（優先順）

1. **Stripe の支払いリンクに確認の1文を足す。** ダッシュボード → 支払いリンク → 編集 → 「カスタムテキスト」の送信ボタン付近。
   例: 「月払いは毎月、年払いは毎年、解約するまで自動で更新されます。解約はいつでも、届いたメールのリンクからできます。条件の全文: https://zenginpon.kokokikaku.com/pricing.html#confirm」
   あわせて「利用規約への同意を求める」を有効にし、Stripe の公開情報に規約とプライバシーポリシーのURLを設定する
2. Stripe・Google・GitHub の二段階認証を確かめる
3. テスト購入で、メール到達 → キー有効化 → 解約 → Free に戻る、を通す
4. 実銀行で1件の取込テスト
